# PyMC Challenges

Worked examples and **hard, real-data challenges** for Bayesian modelling with the current
PyMC stack (**PyMC 6 · ArviZ 1 · PyTensor 3**). Every challenge dataset is real; a few examples
(E47, E48, E51, E52, and parts of E46, E50 and E58-E61) simulate systems with no public data, and say so. Every challenge ends
in a decision somebody actually has to make, and in every one the obvious first model
breaks in a way you have to diagnose.

Hints are there if you want them - tiered, opt-in, and tracked, so you know how much help
you really needed.

## Setup

Requires [uv](https://docs.astral.sh/uv/).

```bash
uv sync                          # creates .venv with PyMC 6, ArviZ 1, nutpie, JAX, JupyterLab, ...
uv run python -m pymc_challenges # optional: (re)download all datasets into data/
uv run jupyter lab notebooks
```

Using VS Code or another IDE instead? Point it at the interpreter in `.venv`.

On Linux x86_64 with an NVIDIA GPU, `uv sync --extra gpu` installs CUDA 13 JAX. A CPU is enough
for every notebook, so this is optional. Later syncs drop it unless you repeat the flag:
`uv sync --extra gpu --extra reports`.

## How to use this

```
notebooks/
  examples/      E01-E92, E94-E119  modelling techniques; D01-D03 data preparation and analysis. Worked, narrated, executed.
  challenges/    C01-C15  your workspace. Tasks, empty cells, hints on request.
  solutions/     C01-C15  full reference solutions, executed, with commentary.
```

1. Work through the **examples** first if you are new to PyMC 6 - the API has moved
   (`DataTree` instead of `InferenceData`, `pm.Data`, new ArviZ plot names). **E01** has a
   then-vs-now table.
2. Open a **challenge**. Each task tells you *what to deliver*, never how.
3. Resist the solutions folder. Use the hint ladder instead.

### Hints, checks and progress

Each challenge notebook creates a helper `h`:

```python
h.tasks()                          # list tasks, and how many hints / checks each has
h.hint("task2")                    # reveal the NEXT hint for task2
h.hint("task2", level=3)           # or jump to a level
h.check("task2", sigma_angle_deg=1.5)   # compare your number with the reference solution
h.progress()                       # hints used, checks passed
h.reset()                          # start over
```

Hints always come in three levels, revealed one at a time:

| level | name | what you get |
|---|---|---|
| 1 | **nudge** | a question or a concept - where to look |
| 2 | **approach** | the modelling idea spelled out, and the PyMC/ArviZ API to use |
| 3 | **skeleton** | code structure with the key parts left blank |

A good target: solve a challenge on nudges alone. Checks use generous ranges (different
priors and seeds will pass) but will catch a wrong model or wrong units. Your hint usage is
stored locally in `.progress/` (git-ignored).

#### Posteriors as labelled arrays: xarray for Bayesian work (E42-E44)

A posterior is a labelled array with named `chain`, `draw` and model dims. These three notebooks

#### Exposed versus unexposed (E101-E103)

A brand lift study without a holdout compares people who saw the ads with people who did not, and corrects the comparison with propensity scores. Criteo's uplift data hold both that study and the randomised experiment that grades it. The experiment, adjusted for a small imbalance between its arms that 14 million rows reveal, puts the effect on the exposed at 21 points for site visits and 2.8 points for conversions. A Bayesian propensity analysis done by the book (balance within 0.074, four estimators that agree) says 26 and 4.5. The conversion overstatement holds against the unadjusted experiment too (3.2); for visits it depends on the adjustment (unadjusted, 28.7, the propensity estimate would look low). Adding features converges to the wrong answer. Replayed at survey size, the experiment is noisy and centred while the propensity estimate is tight and stays biased, its coverage falling from 74% to 1% as the survey grows. Runs in about 4 minutes, about 2.2 GB.

E102 asks which way such a study goes wrong. On the 45,100 control users, whose observed visits are their no-ad visits, it keeps the real features and visits and simulates only who sees an ad, hiding what one feature knows about visiting from the analyst; the true effect is zero, so every estimate is its bias. Delivery that leans toward the hidden engagement trait overstates the effect (+5.5 to +9.1 points at E101's 3.6% reach, E101's own error was +5.7); leaning away from it, a suppression list of engaged users, or a retarget-then-prospect plan scaled past 10% reach understates it, by up to 7.6 points. In this simulation, reach alone did not flip the AIPW bias of a fixed delivery rule (IPW's estimate did cross zero for strong retargeting at 50-80% reach), but reach changes the size: the threshold-model gap in the hidden trait is U-shaped, while the bias in points shrinks with reach under retargeting-like delivery because the visits sit in the top tail of the trait. At 95% reach each effective unexposed user stands in for 32-45 exposed ones and the imputed baseline is off by a factor of 1.75-2.4 wherever delivery used the hidden trait, so high reach is the worst case for relative lift and overlap. A full Bayesian analysis reports a campaign with a true 4.7-point effect as +0.1; balance and overlap look the same as in a mirror-image world where it reports 12.0, and a sensitivity model and E-values cannot tell the sign. E101's visit bias is positive against its adjusted experiment and would be negative against the unadjusted one. Runs in about 2.5 minutes, about 1.4 GB.

E103 asks whether a brand team with many campaigns, all measured by propensity scores, can get by with a few holdouts. It builds 720 campaigns of three targeting types (retargeting, broad with suppression lists, prospecting) on E102's real users, in four worlds where the bias is more or less predictable from the type, and gives a few of each 40-campaign portfolio a ghost-ad holdout survey drawn from real rows. A propensity estimate is exactly its true effect plus the placebo bias, so campaigns get fresh true effects and break-even costs. A hierarchical model of the bias across campaigns, with type and reach as covariates and a spread tau, is fitted in PyMC after the latent-effect version hits a funnel in tau; it calibrates the untested campaigns, and an exact grid posterior of the same model, matching NUTS to 0.1 point, scores 1,080 holdout plans. Raw propensity estimates lose the portfolio's whole value (regret 0.72 against an oracle's 0.69 points per campaign); when the bias follows the type, 8 calibrated holdouts of 40 cut regret to 0.16-0.20, against 0.32-0.33 for deciding from the experiments alone, and calibrated intervals cover 86-96% against 2-21% raw. When the bias is unpredictable the gain over experiments alone is within noise and a pooled model beats the covariate one. Testing only retargeting makes a pooled correction worse than none for the other types; a hidden hunch about which campaigns to test biases the calibration by about a point. Runs in about 2 minutes, about 1 GB.

#### Spend before the sell-out (E104-E106)

A platform selling many capacity-limited events buys media for each one and lines the events up by days until the event. No public ticketing data include spend, so E104 uses the Hotel Booking Demand data (Antonio, de Almeida & Nunes 2019, CC BY 4.0): each arrival date at a hotel is an event, its real kept bookings over the last 17 weeks are the no-ad baseline, and media spend with a known effect (beta = 0.15), carryover and a room limit is simulated on top. A recording gap on the booking-date clock (bookings made in late 2015 are missing) sets the window. Over 27 simulated worlds a fast Poisson panel shows which habits mislead the t-minus model: stopping spend at sell-out doubles the estimate (dropping or censoring the sold-out days fixes it), seasonal spend nearly doubles it without calendar terms (week terms leave +7%; booking-date effects remove it), spend timed to each type's curve adds a fifth with one pooled curve, reactive pacing takes off a seventh and outcome-based pace controls move it either way (an instrument built from the pacing rule's random factor recovers the truth), and brand spend that is the same for every event is not identified once booking dates have effects. #### What a hidden confounder can do (E107)

An observational estimate rests on the claim that nothing unmeasured drives both treatment and outcome; E107 shows what breaking that claim does and how to report the risk, on the job-training benchmark where the truth is known. The randomised NSW experiment (Dehejia-Wahba subset of LaLonde 1986, via the MIT-licensed `causaldata` package) puts the effect on 1978 earnings at \$1,794. NSW trainees against 15,992 CPS men give -\$8,498 raw and \$1,572 with a flexible specification including 1974-75 earnings; hiding the earnings history turns that into a confident -\$3,690, and replacing the trainees by the randomised controls (true effect zero) measures the bias directly: \$4,264 with demographics, \$40 with the flexible set. Synthetic confounders planted on the real rows match the omitted-variable-bias formula to the dollar: a confounder with 3% of leftover variance on both sides reverses the estimate or hides an effect of \$1,850, and stays invisible to a balance table of the measured covariates. In the partial-R2 form of Cinelli & Hazlett (2020) the robustness value is 2.2% (0.67% for significance), with the code (bias and standard error) checked against the paper's Darfur example; a confounder as strong as the 1975 earnings block cuts the estimate to \$409, single-variable benchmarks understate, and an analyst who never measured earnings, benchmarking on demographics, would have allowed a ninth of the hidden block's share of outcome variation. E-values give a wrong-signed employment estimate about the same robustness as the right one; the matched design most analysts would build first is not significant at Gamma = 1, and the experiment itself, read as pairs, loses significance at Gamma = 1.13. In PyMC a latent-confounder model returns its priors, benchmark priors give \$360-2,590 and -\$600 to \$3,690 (both covering the truth), and a binary latent confounder on employment "learns" a huge effect from misspecification of the outcome model; compared on a collapsible scale by g-computation, it puts the trainees' employment gain at about 21 points against 11 in the experiment. A placebo on 1975 earnings fails because of the pre-programme dip while the 1978 estimate is nearly unbiased. It ends with three demonstrations an analyst can repeat on their own data, a tipping-point sentence that leads with the benchmark, and a stakeholder sensitivity table in plain units that shows why the equal-strength robustness value overstates what a realistic, lopsided confounder needs. Runs in about 2 minutes, peak about 0.7 GB.

#### One day is not your diet (E108)

"Nine in ten Americans eat too much salt" is a usual-intake claim, and a single 24-hour recall cannot make it. E108 treats each NHANES 2017-2018 recall as a noisy reading of a hidden usual intake. It uses 4,863 adults, 4,240 of them with a second recall, and fits a replicate-measurement deconvolution model in the spirit of the ISU and NCI methods. The model works on a Box-Cox scale, with cell-level within- and between-person variances, a phone-day and a weekend term, and a Gauss-Hermite back-transform to milligrams. A toy with a known truth shows the "squeeze", and there is a funnel in the between-person scales with its fix (a centred/non-centred mixed parameterisation). Weighted to the population, 74% of single days are over 2,300 mg, against about 86% (85-88%) of usual intakes, close to the CDC's 89%. One day exaggerates both tails (under 1,500 mg: 9% against 1%). With the person effects integrated out, the second recall is seen to identify the variance split exactly: day 1 alone returns the prior, and 300 second days are nearly enough. The richest income band is very likely (98.9%) more often over the line than the poorest, by about 6-7 points, but the gap's size is uncertain because the simpler model understates the one-day gap. A correlated two-part hurdle model for alcohol, with never-drinkers from the questionnaire, separates days over the daily limit (16%) from people averaging 15/8+ drinks a week (16%), and a frequency tree shows how badly one day sorts them. The public side is a hypothetical-outcome-plot GIF of 100 seats, its still and flip-rate map, an icon-array ladder with honest uncertainty, and a calibrated-language strip, set beside the statistician's interval plot. Runs in about 3 minutes, peak about 2 GB.

#### Counting the uncounted (E109)

How many people killed in Kosovo in 1999 were on none of the four lists that recorded the dead? E109 answers with multiple-systems estimation on the real capture-history table of Ball et al.'s (2002) report to the ICTY (4,400 named people; LCMCR, GPL), and on the UK's 2013 modern-slavery lists behind the Home Office's 10,000-13,000 estimate (SparseMSE, GPL). Two-list Lincoln-Petersen estimates (5,500-9,700) are all below the published 10,356, mostly because of positive dependence between lists. Independence and pairwise log-linear models miss 10 and 5 of the 15 cells. The plain horseshoe gives about ninety divergences and the regularised one none. With three-way terms, the horseshoe gives about 9,300, nearly flat interaction priors 11,200-11,500, and about 14,000-15,000 once the main effects are left wide too (saturated MLE 17,000). A latent-class model with the classes summed out gives 10,400, beside the published 10,356. Averaging over 113 hierarchical log-linear models gives 10,900 and moves with the prior (Madigan & York's own method gave Silverman 12,600). PSIS-LOO fails in most cells, so stacking uses 60 exact leave-one-cell-out refits. The headline stacks the two models that fit: about 13 people on no list for every 10 listed (10-18), and very likely (95%) at least 4,300 unlisted. A ridgeline prices the dependence assumption: a total near 17,400 needs the ABA and HRW lists to overlap twice as often as chance, where the model puts them a little below it. On six sparse UK lists the latent-class answer doubles (22,000 against 10,300) because of one list. On Silverman's four-list table the two models come within about a fifth of each other (9,800 and 12,000). The public figures are an iceberg icon array with solid, hatched and dotted squares, a quantile dotplot, a 40-frame HOP GIF, an overlap chart whose missing column is filled in, and a 100-world swarm. Runs in a little over 3 minutes, peak about 1.1 GB.

#### Is the bar the same for everyone? (E110)

Raleigh police found contraband in 16.5% of searches of Black drivers and 14.2% of white drivers; does that clear them of searching Black drivers on less suspicion? E110 uses 856,400 stops from the Stanford Open Policing Project (ODC-By) to show why the outcome test cannot say. Two invented groups held to the same 10% bar have hit rates of 42% and 23%. One city's two rates fit every bar from 0.2% up to its hit rate exactly. The threshold test replaces it: a hierarchical latent-threshold model over 214 officers and a pooled unit, with the closed-form discriminant family and a logit-normal family by 16-node Gauss-Legendre quadrature. A level ridge leaves race-level r_hat at 1.04-1.07 while the gaps mix. Lower priors that cover the data move the level, not the signs. The posterior checks are nearly saturated and could not fail. Both shapes put the bar for Hispanic drivers 2.3-3 points below white drivers'. For Black drivers the sign flips with the shape (-0.3 vs +0.5), and PSIS-LOO cannot choose. In placebo worlds with equal bars, a wrong shape invents gaps of 1-4 points, and 3 of 8 zero gaps get >99%, but the two shapes never agree on a false gap. Public side: natural-frequency trees of 10,000 stopped drivers beside gradient-strip gaps, a bar-and-hit-rate ladder, a value-suppressing beeswarm of officers and calibrated words, set against the hit-rate bar chart and forest plot. Runs in about 5.5 minutes, peak about 1.2 GB.

#### The path we were on (E111)

How much life expectancy did each European country lose to COVID against where it was heading, and is it back on that path? E111 fits Lee-Carter mortality as one negative-binomial PyMC model pooled over 30 countries (Eurostat deaths and populations 2000-2024, CC BY 4.0). It first corrects three census breaks by age and checks a fourth that the population total hides. A free softmax row fails with r_hat near 1.9 and no divergence to warn, and zero-sum rows fix it. A hand-written likelihood is timed at 1.8x PyMC's. A 2015-2019 backtest fails (46% inside a 90% fan, every miss below), so a shared European random-walk error widens every path. Europe was about 1.3 years below its path in 2021 (0.6-1.9, virtually certain) and about half a year below in 2024 (likely, 74%, low confidence). By 2024, 17 of 30 countries are likely still below and 13 can't be called (45-65%). That split moves with the jump-off choice (18 and 12). Poisson counts cover 74% of cells against 92.6% and push the noise into the trend. The public figures are a graded fan for each country on a tile-grid map, risk-equivalent ages as quantile dotplots, a 100-world swarm of about 2 million excess deaths (0.3-3.5 million, more likely too high than too low), and a German mortality carpet. Runs in about 3.5 minutes, peak about 1.7 GB.

#### How many children in your county are poor? (E112)

The survey says a third of the children in a small county are poor, give or take ten points: is that real? E112 fits Fay-Herriot small-area models to 3,142 US counties using two non-overlapping ACS 5-year samples (2019-23 and 2014-18, table B17020), checked against the Census Bureau's SAIPE 2023 (all public domain). A classic logit model looks right for the counties with zero estimates only by accident of the delta method. The two surveys disagree beyond three margins for 2.9% of counties, about eleven times what the margins allow, almost all of them small. Churn that scales like sampling variance does not explain the excess, and SAIPE sides with the recent survey barely half the time. A variance function with the published variances as scaled chi-square (Gamma) data believes the zeros (Mason County, Texas, at 6%). Student-t survey errors win marginal LOO by 32 ± 10 yet explain away the reservations (Corson County, South Dakota, from 60% to 19%), and giving the county effects t tails as well does not help. The two-survey model with t errors and t effects keeps Todd County at about 57%, brings Mason back to 18% and roughly reproduces the disagreement rate (3.5% replicated against 2.9%). Its limits: it trusts the wrong survey in Tunica, Mississippi, it sits about 3 points below SAIPE in small counties, and it cannot see a bias common to both ACS samples (SAIPE is 6-19 points lower on the reservations). The public side is a Bayesian surprise map: 8 counties stand out, 7 Dakota counties with reservations or tribal land higher than expected and Los Alamos lower, and the count runs from none to 276 as the spreads are doubled or halved. It sits beside a value-suppressing estimate map, quantile-dotplot "find your county" cards, a shrinkage beeswarm and a rank ladder, set against the raw choropleth and a caterpillar plot. Runs in about 4.5 minutes, peak about 2.5-2.8 GB.

#### Is the 100-year flood still a 100-year flood? (E113)

My house is just outside the "100-year floodplain": what is the real chance it floods during a 30-year mortgage? E113 writes Bulletin 17C's log-Pearson III in PyTensor for 12 USGS gauges on the Susquehanna, Potomac and Schuylkill (public domain). It treats the floods of 1786-1889 as censored data, with a latent perception threshold summed out exactly. PyTensor's incomplete-gamma derivative in the shape is wrong by orders of magnitude at these rivers' shapes, so the tail comes from a 48-node quadrature. A clamp that kept the density finite rewarded a mean of 10^33 cfs, and a centred location strands chains at the moving support at two seeds in five. History lowers the 100-year flow by about 8% and narrows its range by a third; a hierarchical skew pools the gauges at 0.26. Yearly peaks are probably about a tenth lower than before mid-century. But the gauges' peaks correlate at 0.56, worth fewer than two independent gauges, so the models are compared by LOO leaving out whole water years. The decline's lead over no change becomes 4 ± 9, and stacking gives no change a third of the weight. Over 2025-2054 the textbook 100-year flow is *unlikely* to be beaten (about 11%, 3-22%, low confidence: about 8% if the drop is real and lasts, 14% if not), against the 26% its name implies. The public figures are chance-of bars over a 30-year mortgage with gradient whiskers and printed ranges, a "what would change our mind" strip, and a flood-marks HOP GIF on a bridge pier. The return-level plot serves as the statistician's contrast and the posterior predictive check. Runs in about 4 minutes, peak about 1.9 GB.

#### Is this fish being overfished? (E114)

When I buy cod, sole or hake, is the stock in the sea healthy? E114 fits a Bayesian Schaefer state-space model to 18 stocks from the RAM Legacy database (CC BY 4.0). The states are free (centred); a non-centred scan gave r_hat 1.6. A smooth floor and a feasibility penalty make the catch come out of fish that exist. FishBase-CMSY growth priors get family effects only where a family has several stocks, and one shared process noise replaces per-stock noise, which gave 114 divergences. A toy shows why a one-way trip of catches leaves r and K on a ridge. In their last year of data about 6 of the 18 stocks (3-9) were below B_MSY, and it is *very likely* (94%, low confidence) that at least 4 were, though not which; only ling was more likely than not overfishing. Against 14 official assessments the model is usually the optimist: it calls none of the three officially overfished stocks overfished. Georges Bank yellowtail's status turns on the process noise and on two survey spikes. Catch-only northern cod comes out near twice B_MSY in 1992, against an official 5%; neither CMSY's end filter nor a lower floor fixes it. The public figures are 40 possible histories per stock with counted titles, fish-icon rows with official-status marks, an MSY gradient band, prior-to-posterior strips and a HOP GIF. Runs in about 3.5 minutes, peak about 1.1 GB.

#### The last bag of fertiliser (E115)

Should a farmer spread a third bag of nitrogen? E115 fits 74 years (1852-1925) of the Broadbalk wheat experiment at Rothamsted (agridat, MIT; credit Rothamsted Research and the e-RA). It uses a Mitscherlich curve under a latent AR(1) year potential, with soil nitrogen that runs down and manure that builds up, a literal law of the minimum that loses to a partial one, and shrunk effects for unreplicated strips. Every treatment mean matched while the replayed yearly increments were twice as spread out as the real ones. A year-by-dose term and a noise scale per strip fixed that and gained about 260 points of elpd. The third bag paid on average (>99%), but on one plot in a given year about 8 times in 10, and 9 in 10 with the weather alone. The economic optimum at cheap nitrogen turns out to be mostly the curve. The public picture is prediction beside inference: paired 50-dot quantile dotplots on one axis, with a price-dial GIF. Runs in about 5 minutes on 8 cores, peak about 1.1 GB.

#### Is my toddler on track? (E116)

Is my two-year-old, who says about 50 words, on track? E116 fits a two-parameter item response model to 9,537 Wordbank checklists of the 680-word MacArthur-Bates CDI (American English, CC BY 4.0; the build stops if a CC BY-NC dataset ever enters the slice). Each child's ability is integrated out through a sharpness-weighted score with adaptive Gauss-Hermite quadrature. A common grid misses the needle-thin posteriors, free section means drift along an exact ridge (r_hat 1.43), and counting by cells is 14 times too sure. A monotone growth curve learns an advanced 28-month sample, and a smooth curve with orthogonal month deviations fixes it. A two-step horseshoe flags 18 words that one sex learns earlier at the same vocabulary. A split-half test shows that words hang together by section, 1.6-3 times beyond the model, and each child's likelihood is tempered to match. Held-out children show the published lowest-10% line holds only 8.4% of children, so the percentile scale is corrected empirically, with bootstrap uncertainty. A 50-word two-year-old is around the 10th percentile (6th-14th) and *about as likely as not* (55%, medium confidence) to be in the lowest 10%; the uncorrected model said 21%. The public figures are "you are here" quantile dotplots under a graded growth fan with a 0-100 locator, a first-words ladder of gradient intervals with natural frequencies, and a calibrated-language strip. Runs in about 3.6 minutes on 8 cores, peak about 1.9 GB.

#### Would that headline finding replicate? (E117)

Is a newly published psychology finding real, and would it show up again? E117 models 76 original-and-repeat pairs from the Reproducibility Project: Psychology (OSC 2015, CC0) as a null/real mixture. It writes a step publication filter into the likelihood in closed form, with the weight and the probability of publication read from one z-statistic, and checks it against quadrature. Ignoring the filter expects 56 successful repeats where 26 happened. The filter alone loses to "about 1 in 3". A share per field and an imperfect repeat (λ about 0.78, between-site spread about 0.19), added after that, give an exact 10-fold track record of 28 expected against 26, but within one standard error of each field's base rate, and too spread out (calibration slope 0.6). About 65% of published findings like these are real (93% cognitive, 41% social), and that "most are real" is *virtually certain* (99.3%, medium confidence). In simulated worlds where only 45% are real, the model overestimates but never says virtually certain. A news reader's table separates P(real) from P(replicates). The public figures are a track-record plot against the field rule, icon shelves with partial fills, a risk ladder, word strips and a publication-filter GIF. Runs in about 1.5 minutes, peak about 1 GB.

## Website (GitHub Pages)

`tools/build_site.py` renders every example, challenge (with its hint ladder) and solution into a
static website - narrative, maths, code, figures, tables, animations and plotly figures - plus a
landing page, a catalogue, a "choosing a model" guide and a challenges overview. Nothing is
re-executed; the pages come from the outputs stored in the notebooks.

```bash
uv run python tools/build_site.py      # -> _site/ (~75 MB, a few seconds)
python -m http.server -d _site         # preview at http://localhost:8000
```

`.github/workflows/pages.yml` builds and deploys it on every push to `main` that touches the
notebooks or the site sources (set *Settings -> Pages -> Source* to **GitHub Actions**). Site prose
lives in `tools/site_content.py`, styles and scripts in `tools/site_assets/`; per-notebook titles,
data and techniques are read from the curriculum tables above, so keep those up to date.
[AUTHORING.md](AUTHORING.md) lists what to register for a new notebook, including the home page's
"Recently added" section, which always leads with the newest examples.

The site shares the look of [redam94.github.io](https://redam94.github.io/): white, mist and black
surfaces, one olive accent, system type. `tools/site_assets/figures.js` draws the interactive figures
on the home page (a live HMC sampler, a posterior that updates, the workflow track); `site.js` holds
the smaller enhancements (theme, code toggle, example filter, reading progress). Every page still
reads with scripting off.

The photographs and icons in `tools/site_assets/img/` were generated with fal (`fal-ai/nano-banana-2`)
and converted with `cwebp`: `backdrop-<name>-2000.webp` and `-1100.webp` sit behind the black sections,
and `icon-<series key>.webp` (512 px, object on pure black) is the icon of one series in
`site_content.SERIES`. A new series without an icon gets a blank black tile, so add
`icon-<key>.webp` when you add the series.

## Running on a laptop with limited memory

Multiprocess samplers copy the model once per chain, and a notebook kernel keeps everything
alive until it exits. If memory is tight, run builds (or any script) under the guard, which
kills the whole process tree above a cap and otherwise reports the peak:

```bash
uv run python tools/memguard.py --max-gb 3 -- python tools/build.py C10
```

Every notebook here has been measured this way and peaks below 3 GB (most between 1 and 2 GB).
If your own solution to a challenge balloons, `tools/memprofile_nb.py` reports memory cell by
cell. The usual culprit is model comparison: after `loo = az.loo(idata, pointwise=True)`, free
the two big arrays with `loo.log_weights = None` and `del idata["log_likelihood"]`.

## Rebuilding the notebooks

Notebooks are generated from jupytext sources in `notebook_src/`; a challenge and its
solution come from **one** source file so they cannot drift apart.

```bash
uv run python tools/build.py            # rebuild and re-execute everything (slow)
uv run python tools/build.py C03 E02    # just these
uv run python tools/build.py --no-execute
```
